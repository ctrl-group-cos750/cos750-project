# Open Questions: module-map-and-progress

| # | Question | Recommended Answer |
|---|----------|--------------------|
| 1 | **Segment ↔ Video/Activity FK direction.** SE §8 puts `segment_id` on Video and `activity_id` as a general concept. Should Segment hold `video_id` and `activity_id` FKs (segment points to its content), or should Video and Activity hold `segment_id` (content points back to its segment)? The SE doc says Video has `segment_id`; but Segment also logically needs to know its content. | **Both directions, but Segment is the owner.** Add `video_id` and `activity_id` nullable FKs on Segment (so the module page can load segments with their content in one query). Also add `segment_id` on Video as the SE doc says (the video knows which segment it belongs to). This matches the ER diagram: `SEGMENT |o--o| VIDEO` and `SEGMENT |o--o| ACTIVITY`. The redundancy is small and avoids N+1 queries. If you prefer one direction only, say so and the plan will adjust. |
| 2 | **`react-markdown` version.** The plan calls for `react-markdown` at a pinned exact version. The latest stable as of the plan date needs confirming. The developer should verify via Context7 or npm before installing. Are you OK with `react-markdown`, or do you prefer a different Markdown library (e.g. `marked` + `DOMPurify`, `markdown-it`)? | **Use `react-markdown`.** It renders to React elements (no `dangerouslySetInnerHTML`), so it is inherently CSP-safe. It's well-maintained (remarkjs ecosystem), React-native, and the most popular choice. The developer will pin the exact latest version at install time. |
| 3 | **Module completion trigger.** When the student reaches the last segment and clicks "Next", should that automatically mark the module complete? Or should completion require all segment activities to be answered correctly first? The scope note says activity renderer is out of scope for this story. | **Mark complete on reaching the last segment position for now.** Since the activity renderer isn't in this story, we can't gate on activity correctness yet. Add a `TODO` comment that a future story (the activity story) should add a check that all required activities in the module are passed before allowing completion. The position-save endpoint can set `status="complete"` when `segmentPosition >= last segment`. |

This also validates that the seed handles real-length strings. |
| 5 | **ModuleProgress composite key vs surrogate.** SE §8 shows `user_id` + `module_id` as the conceptual key for ModuleProgress. Should the table use a composite primary key or a surrogate `id` with a unique constraint? | **Surrogate `id` primary key + `UniqueConstraint("user_id", "module_id")`.** This matches the project's existing pattern (every table uses `id` as PK — User, Activity, Attempt, Video, Checkpoint, etc.). A composite PK would break the convention and might confuse SQLAlchemy's `session.merge()` usage. |
